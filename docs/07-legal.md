# 合规边界

这套工具流的定位是**技术学习与安全研究**。边界必须清楚，否则风险完全不对等。

## 硬红线（不要碰）

- 分发从别人游戏里提取的任何资源、代码、程序集，包括放公开 git 仓库
- 制作或传播破解补丁、外挂、绕过付费/DRM 的工具
- 逆向线上服务的反作弊、支付、账号体系并加以利用
- 攻击、压测、爬取对方服务器
- 抄袭美术资产、音乐、剧本等受著作权保护的内容
- 把逆向所得直接用于商业竞品的克隆

## 相对安全区

- 分析技术方案、架构组织、工程实践，写成不含原始素材的笔记
- 学到的**思路**用在自己的项目上——软件的功能与思想本身不受著作权保护，具体表达才受
- 单机游戏的个人 mod（仍需看 EULA，很多明确禁止逆向）
- 有明确安全研究豁免或漏洞奖励计划下的分析

## 实操约定

1. **本仓库只提交工具与方法论，不提交任何游戏产物。** `.gitignore` 已经排除 `targets/`。
2. 反编译产物用本地 git 仓库做版本对比，不设远程。
3. 报告对外分享前删掉：代码片段、资源截图、可定位的字符串、服务器地址。
4. 逆向前扫一眼目标的 EULA / 服务条款。很多明文禁止 reverse engineering——虽然部分司法辖区对"互操作性目的"有例外，但你的具体情况请自行判断。
5. 目标优先选：已停运的游戏、单机、有 mod 社区且官方默许的、自己公司的历史项目。风险从高到低排序时，在线竞技网游是最高风险的一类。

## 一句话

**学别人的思路，不搬别人的东西。** 产出是笔记和自己写的复现代码，不是从别人包里拷出来的文件。
